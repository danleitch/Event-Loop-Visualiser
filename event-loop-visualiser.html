Things that go in the microtask queue 🚨

Each one is a small job that waits in the higher-priority line and runs as soon as the current code finishes.

  • .then(() => {...}): runs when a promise succeeds. Like a teacher saying "when your essay is marked, come see me".W3Schools: Promises
  • .catch(() => {...}): runs when a promise fails. Your Plan B if something goes wrong.W3Schools: Promises
  • .finally(() => {...}): runs whether it worked or failed. Tidying up at the end, no matter what happened.W3Schools: Promises
  • await (inside async function): pauses this function until a promise is done. Everything after the await goes in the higher-priority line.W3Schools: Async
  • queueMicrotask(() => {...}): puts a small job straight into the higher-priority line, without making a promise first.MDN: queueMicrotask
  • new MutationObserver(() => {...}): a watcher. You tell the browser to watch part of the page, and when something changes (an element is added, removed or edited), your function goes in the higher-priority line. It's how code reacts to the page changing without checking all the time.MDN: MutationObserver
